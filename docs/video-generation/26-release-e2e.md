## 测试入口

```powershell
npm.cmd run build:windows
npm.cmd run test:release-e2e
npm.cmd run test:world-offline-desktop-e2e
```

两套桌面测试默认运行 `src-tauri/target/release/mojing.exe`，也可在命令末尾用 `-- <exe绝对路径>` 指定待测程序。需要 Windows、WebView2、Node.js 24、已安装的项目依赖，以及 PATH 中的 FFmpeg / FFprobe。

`test:release-e2e` 使用发布程序自带的前端，不依赖 Vite 或源码模块导入。脚本通过 CDP 操作真实 WebView2，通过属于本次进程的 Windows 原生保存对话框导出成片。

## 覆盖范围

| 操作 | 核验内容 |
| --- | --- |
| 在界面新建项目并粘贴剧本 | 项目创建不调用模型；剧本进入真实切片、分镜规划和实体提取 |
| 确认分镜规划 | 确认之前没有图像请求；确认后生成角色、场景和每镜两个关键帧候选 |
| 关键帧审核 | 未审核时不生成视频；拒绝关键帧后生成按钮禁用；通过后才能继续 |
| 继续生产 | 真实音色分配、两次 TTS、两镜共四个视频候选、技术检查、视觉审核接口和人工锁定 |
| 合成 | 真实原生文件读写和 FFmpeg；FFprobe 核对 H.264、AAC、尺寸、240 帧和约 10 秒时长 |
| 内容核对 | 解码两镜画面，核对红／蓝顺序；解码 PCM 并检查两段音轨的实际 RMS |
| 编辑时间线 | 界面调整顺序，用键盘操作滑块裁剪 1 秒；旧成片失效；重新合成后顺序翻转、时长约 9 秒；播放器加载新时长，并通过屏幕像素检查确认显示新画面 |
| 界面布局 | 深、浅主题截图及 900×600 最小窗口；播放器保持在预览卡片内、不遮挡时间线，时间线保留可操作高度；滚动后镜头排序按钮能实际命中 |
| 导出 | 点击导出按钮，通过真实 Windows 保存对话框保存 MP4，再检查导出文件的视频、音轨和时长 |
| 无限画布 | 通过文件控件导入两节点输入文档；依次生成图片和视频；核对上游图像进入下游首帧请求、结果真实落盘 |
| 素材回流 | 在画布将视频发送到项目分镜，生成未审核参考候选，保留当前锁定版本和成片；素材库能播放磁盘视频 |
| 退出重开 | 结束整个应用进程，使用同一隔离数据目录重开；核对项目、审核记录、裁剪、画布输出与视频播放 |

`test:world-offline-desktop-e2e` 另外验证世界引擎的原生逐帧输出：24 帧、1280×720、24 fps H.264 MP4。解码两机位画面，检查场景有可见内容、切镜前后的像素实际变化；完成后进入素材库，实际播放并在页面重载后恢复。

## 模型测试边界

仅远端模型边界由本地 HTTP 服务模拟，包括分镜 LLM、Agnes 图像／视频、TTS 音频和视觉判断。测试服务返回有效 PNG、带动态画面的 MP4 和有声 MP3；视觉审核返回固定测试判断。

Provider 适配器、Rust HTTP 请求、轮询、输入参考读取、素材下载保存、审核门禁、FFmpeg、Windows 保存对话框、WebView 播放和持久化都使用应用实际代码。测试不覆盖或替换 Tauri IPC，也不向业务状态中注入生成结果。只预置测试接口配置，并通过正常文件导入入口提供画布输入。

通过测试说明制作链路可用，不能说明真实模型画质、模型账号权限、外部服务稳定性或真实配音自然度达标。Seedance / 小云雀的真实账号联调也不在这套测试范围内。

## 数据与产物

每次测试使用唯一 WebView2 数据目录和本地服务端口，不读取真实用户的模型密钥或项目。原生保存对话框只定位本次应用进程，写入本次测试目录。结束时仅清理本次创建的项目目录与已核对归属的素材文件。

成功后保留 `artifacts/release-e2e-<时间>/`，包含原始成片、剪辑后成片、界面导出文件、各阶段截图以及 `report.json`。报告记录程序 SHA256、模型请求数量、输出参数、画面颜色、音频测量和布局检查。世界引擎测试在 `artifacts/world-desktop-e2e-<时间>/` 保留 MP4、导出与素材库截图及报告。失败时保留截图和诊断信息。

原生保存助手同时按进程归属、控件编号和控件类型定位文件名输入框，回读完整路径并等待对话框关闭；拒绝覆盖已有文件，避免 Windows 同编号的地址栏控件导致误保存。

测试运行的是 NSIS 构建所用的发布程序；不会覆盖用户原有安装，安装向导升级／卸载不属于本次自动验证。

## 0.3.1 修复的回归

1. `VideoPipeline.forResume` 曾对所有视频项目使用空章节，导致粘贴剧本的新项目首次规划失败。现在从项目源章节／剧本恢复输入，并保留小说项目的章节选择范围。
2. 修改镜头顺序、启用状态、裁剪或音量曾保留旧成片。现在有效编辑会清空旧成片及其元数据；实际重新合成后再标记合成完成，避免误导出旧剪辑。
3. 重新合成覆写同一个 `final.mp4` 时，WebView2 曾缓存旧视频分片，导致磁盘文件已更新而预览仍播放旧成片。现在本地预览 URL 使用本次合成的完成时间作为版本，并重新挂载播放器；远程视频链接保留原样。

三项问题均通过发布程序界面复现，并由上述 E2E 检查覆盖。

截图复核同时发现时间线容器和镜头卡片使用固定白色背景，深色主题下部分文字不易辨认。已改用项目主题变量。另修复视频固有尺寸撑开预览卡片、遮住时间线标题，以及窄窗口下时间线高度被压到零的问题；保留深、浅主题与最小窗口截图，并检查实际元素边界。
