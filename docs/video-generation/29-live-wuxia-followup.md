# 武侠庭院实片后的生产流程修复

2026-11-18，用户认为第一版六镜试片难看。本轮继续验证同一位成年女主与橘猫大师的跨镜头一致性，先尝试 Agnes 2.5 Flash 的真实首帧生成，不再用独立文生视频代替角色参考。

真实提交使用上轮生成的完整庭院母版作为首帧，模式为 `keyframe`，时长 5 秒。服务再次返回 `503 video_queue_full`，请求 ID 为 `20261118010920701438741vNcDURnI`。没有成功产出新的质量样片，也没有将旧视频重新包装为改善后的结果。H3 现有通道不支持角色参考，上一轮重生成又返回余额不足。本轮尚需一个可用的首帧／角色参考通道，才能继续真实验证画质。

这次实跑也发现了可复现的产品缺陷，已修复：

- 从支持首尾帧的模型切到纯文生视频模型时，会清理不再兼容的首尾帧、主体、音频和视频参考。切回原模型不会重新带出隐藏的旧帧。保留仍受支持的首帧，不会为了移除尾帧而误删首帧。
- 不支持自定义时长的模型显示“由模型决定”，不再提供不能生效的秒数输入。纯文生视频模型会说明其无法通过参考图固定跨镜头人物。支持时长控制的 Agnes 等模型仍保留真实的时长输入。
- 开启字幕烧录后，结构化 `dialogue` 里的台词也会进入合成；旁白为空不会再丢字幕。兼容旧规划将首句对白同时复制进旁白的情况，避免重复显示。静默镜头不使用分镜原文或镜头说明充当字幕。
- 桌面回归继续发现 Windows 缺少 Fontconfig 默认配置时，原字幕路径会失败，并悄悄退回无字幕成片。现在优先使用系统中的中文字体，字幕位置按真实文字高度计算；烧录失败或镜头损坏时明确报错，不再输出缺字幕或缺镜头的视频并宣称成功。

回归覆盖：`test:video-live-regressions`、`test:capabilities`、`test:video-payloads`、`test:timeline`。视频工作台界面端到端验证覆盖了模型切换、时长控件恢复、参考图、媒体参考、素材回流、队列，以及原有画布、世界引擎与电商流程。界面测试使用模拟远程服务，只证明软件行为；上面的 Agnes 首帧请求是独立的真实服务验证。

重建后的原生桌面回归采用正常硬件渲染，通过真实 MP4 画面像素检查确认对白字幕已烧录，并目检了两行中文字幕。缺失一镜会明确失败且不发布部分成片；原生保存、时间线重排裁剪、播放和重启恢复均通过。本机最初的软件渲染测试启动停在空白页，未记为通过。

这些修复解决了错误设置和字幕遗漏，不能据此声称视频画质已经改善。下一步是用可用的参考图视频模型生成两镜，检查女主长相、领口发饰、橘猫脸型体态、庭院位置和动作，再决定是否扩展到六镜。
