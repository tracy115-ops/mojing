# 本地参考素材上传与临时链接

更新：2026-11-16。补齐本地视频只能留在素材库、无法被需要公网 URL 的模型读取的问题。

## 使用步骤

1. 在「视频工坊 → 模型与插件 → 媒体上传设置」配置支持 AWS S3 Signature V4 的 HTTPS 对象存储：endpoint、区域、桶、对象前缀和寻址方式。
2. 填写 Access Key ID、Secret Access Key；使用临时凭证时同时填写 Session Token。配置会保存，凭证仅保留在当前运行内，重启后重新填写。
3. 从素材卡片选择「上传为模型参考」，或在视频参考区选择「上传本地参考」。可以选择已有素材，也可先导入本地文件。
4. WebM 可在上传窗口使用现有桌面 FFmpeg 生成兼容 MP4 副本，转换后自动选中新副本。浏览器不提供假的转码成功。
5. 上传及对象校验完成后，参考区自动选择该素材；生成时将临时签名 URL 发送到 Agnes／Seedance 的原生媒体参考字段。本地原件继续用于预览、编辑和导出。

上传本身不调用生成模型。图像上传支持 PNG／JPEG／WebP，最大 30 MB；音频支持 MP3／WAV，最大 15 MB；视频支持 MP4／MOV，最大 200 MB。读取文件头而非只相信扩展名，并实际探测图片尺寸或音视频尺寸／时长，无法解码的素材在 PUT 前失败。生成时还需满足所选模型更低的大小、数量、时长及组合限制。

## 存储条件

实现的是 S3 签名兼容协议，不是所有对象存储 API 的统一适配。支持路径式 `endpoint/bucket/key` 和域名式 `bucket.endpoint/key`，endpoint 不填桶路径，不附查询鉴权参数。AWS endpoint 例如 `https://s3.us-east-1.amazonaws.com`；区域、桶和寻址必须与服务端配置一致。其他厂商仅在提供相同 S3 协议时使用，未宣称已实测 TOS、OSS、COS 等各家原生 API。

桶必须能被模型通过公网 HTTPS 访问，允许对象 PUT、GET／HEAD。桶可以保持私有，通过签名 GET 链接授权读取。AWS 的 HEAD 在缺少 `s3:ListBucket` 权限时可能用 403 表示对象不存在；恢复时无法区分权限不足与丢失对象会停止，而不盲目重复 PUT。需要按服务端权限模型允许识别不存在的对象，或明确选择「上传新副本」。

浏览器需要桶允许当前应用 origin，并允许上传头、暴露校验头。AWS 格式的 CORS 示例如下，`AllowedOrigins` 按实际运行地址调整：

```json
[
  {
    "AllowedOrigins": ["http://127.0.0.1:1420"],
    "AllowedMethods": ["PUT", "GET", "HEAD"],
    "AllowedHeaders": ["content-type", "x-amz-meta-sha256"],
    "ExposeHeaders": ["content-length", "x-amz-meta-sha256"],
    "MaxAgeSeconds": 300
  }
]
```

桌面 HTTP 使用现有 Tauri 出口；对象存储的权限与公网可读要求仍然适用。浏览器及桌面都使用原始二进制 PUT，不把 Base64 字符串当作文件内容上传。

## 对象验证、恢复与有效期

- 对象键由前缀、日期、任务 UUID 和探测出的扩展名组成，每次新上传独立保存，任务恢复复用同一个对象键。
- 上传前计算文件 SHA-256，将内容类型与 `x-amz-meta-sha256` 一同签入 PUT。上传后单独签名 HEAD，核对对象长度与该元数据。**这是远端长度／元数据校验，不是重新下载远端内容计算哈希，也不承诺存储服务内部的内容校验。**
- PUT 成功但 HEAD 失败时保留任务和对象信息。重试先 HEAD；对象已存在且匹配时只校验，不重复 PUT。网络中断导致 PUT 结果未知时使用相同恢复路径，404 才重新传输；403／校验不一致不会盲目覆盖。
- 已完成任务可「续期读取链接」：HEAD 验证后重新签名 GET，不重新传文件，不请求模型。有效期可选 1／6／24／72／168 小时，默认 24 小时；临时凭证提前过期或存储端撤销权限也会使链接提前失效。
- 生成前及实际执行时重新检查链接，剩余不足五分钟的上传链接不可用。可用的独立公网来源仍可继续使用；支持 Data URI 的模型保留原有本地输入方式。
- 上传任务记录读取／传输／校验阶段，支持取消、失败恢复和重启后的显式恢复。刷新或重启不会自动重新传输。取消仅停止客户端请求，已到达存储端的对象仍保留；后续恢复会先检查它。
- 任务冻结目标桶、区域和寻址方式。更换配置后恢复旧任务会拒绝，需恢复原目标或选择「上传新副本」。同一素材不同时运行两个上传任务，上传中的原件受回收保护。
- 修改原件 URL 会撤销旧上传关联；恢复任务核对来源 URL 的完整 SHA-256 和文件指纹，重新传输时也核对文件 SHA-256。不会持续监测磁盘同一路径被外部程序覆盖的情况。

素材库显示参考链接可用／需要续期，任务页单列上传记录。没有虚构百分比或后台分布式上传队列。新流程不自动删除云端对象；回收本地素材也不会删除云端副本。

## 保存与分享

上传任务与已校验的临时读取链接保存在本机工作区。凭证表单不持久化，Secret Access Key 不进入配置、任务或素材；签名 URL 按协议含 Access Key ID，并可能含临时 Session Token，这些读取链接随素材保存在本机，但不作为可分享配置导出。

素材包、画布／世界导出仍嵌入本地媒体，并去掉上传关联及其临时签名链接。导入媒体不恢复另一个工作区的“已校验上传”声明。模型配置分享继续不包含上传凭证。

## 验证与剩余项

- `test:studio-upload`：GET／PUT／HEAD 的固定签名向量与独立 `aws4@1.13.2` 实现比对，覆盖中文／空格／加号对象键、域名式寻址、临时 Token、签入元数据；检查有效期、文件头、目标隔离、导出剥离和模型引用选择。`aws4` 仅用于生成对照向量，不是应用依赖。
- `test:studio-upload-ui-e2e`：隔离 Chrome、真实三秒 H.264 MP4、PNG 与三秒 WAV、真实二进制与 SHA-256，模拟 S3 和 Seedance。覆盖原生文件选择导入、设置、深浅主题及三种宽度、PUT 后校验失败、刷新后凭证清除与任务恢复、无重复 PUT、参考区自动选择、真实原生模型字段、过期前拦截、续期、取消后的未知 PUT 结果、回收保护、导出脱敏、目标变更及中断任务不自动执行。
- 继续运行视频媒体合同、素材库合同／界面、图像蒙版及整体视频工坊回归。

本轮没有真实对象存储账号联调，也没有调用真实生成模型或消耗用户模型额度。真实 S3 服务的权限、CORS、账单、模型侧访问性和实际画质仍需实际环境验收。

方舟私有素材组、肖像／授权审核、`asset://` 注册上传、小云雀独立 API、多段上传、跨进程断点续传和云端配额／协作尚未实现。通用 S3 上传不等同于方舟私有素材认证。
