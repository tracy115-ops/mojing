# 世界引擎逐帧 MP4 导出

更新：2026-11-16。补齐复杂场景在实时录像时可能跳过画面的问题，增加独立的逐帧导出流程。

## 操作

1. 在「视频工坊 → 世界引擎」搭建场景、设置动作及摄影机；需要切镜时启用多机位序列。
2. 选择材质、白模或深度，点击视口下方「逐帧导出 MP4」。导出使用当前输出机位和世界画幅，监看格子不会拼入视频。
3. 选择长边 1280 或 1920，以及 15／24／25／30 fps。弹窗展示实际宽高、计划帧数和成片时长。9:16 的长边 1920 对应 1080×1920，16:9 对应 1920×1080；其他画幅取最接近的偶数尺寸。
4. 开始后依次显示准备、生成并保存帧、编码并核对视频。帧进度只统计已成功写入本地缓存的帧，编码和核对阶段显示等待状态。
5. 完成后将无声 H.264 MP4 自动保存到素材库，可继续用于现有素材与制作流程。

该入口需要桌面应用及本地 FFmpeg、FFprobe。浏览器可查看导出设置，但不能开始本地导出。原「导出预演视频」继续提供浏览器实时 WebM 录制。

## 时间与画面

导出冻结打开弹窗时的世界文档和渲染模式，并锁定世界编辑。开始前核对当前视口；场景已变化时要求关闭并重新打开。GLB 尚未加载时等待真实模型就绪，资源缺失、加载失败或超过 60 秒则报告失败，避免把占位物当成最终模型导出。

每帧使用 `index / fps` 计算世界时间，同步更新当前输出摄影机、演员走位、姿态和 GLB 动作。启用多机位序列时使用整个序列时长，切镜不会重置对象动画。渲染快慢只影响等待时间；下一帧在上一帧写入成功后才开始，不通过实时录屏补帧。

帧数按 `ceil(时长 × fps)` 计算，并消除接近整数时的浮点误差。输出时长为帧数除以帧率，例如 0.75 秒的序列在 25 fps 下输出 19 帧、0.76 秒。视频最长 60 秒，无音轨。

PNG 逐张写入应用缓存，前端不累计整段图片。编码使用 H.264、CRF 18、yuv420p 和 faststart；完成后 FFprobe 实际解码计数，核对编码、像素格式、宽高、帧率、帧数及总时长，核对通过才保存成素材。

结束、取消或失败后恢复原播放头、渲染模式、画幅、视口尺寸、控制状态和多机位监看。输出始终使用当前输出机位，双／四画面监看只是编辑视图。

## 取消与失败处理

- 准备、模型加载、逐帧生成、编码与核对均可取消。原生端终止本任务的子进程，清理本任务创建的帧缓存，不接受前端提供的删除路径。
- 帧生成失败会清理不完整帧序列，可以重新渲染。
- 编码或核对失败保留完整帧序列，「重试编码」直接重用这些帧。关闭弹窗会清理缓存。
- 离开世界页面会取消尚未完成的任务；如果视频已完成原生提交，则保留已经完成的素材。
- 任务状态目前只保存在当前进程，尚未支持应用重启续导或异常退出后的自动缓存回收。长时、高分辨率导出需要足够的本地缓存空间。

这是现有 Three.js 画面的固定时间逐帧输出，不会自动提升模型生成画质，也不包含离线路径追踪、物理写实渲染、抗锯齿超采样或跨显卡逐像素一致性的承诺。多路独立录像、监看拼屏和音频同步仍待实现。

## 验证

- `test:world-offline`：序列时长、完整帧计数、非整帧时长、偶数尺寸、横竖画幅及导出上限。
- `test:world-offline-ui-e2e`：隔离 Chrome 和真实 WebGL，逐项核对固定采样时间、切镜焦距与人物位置；将真实 PNG 写到临时目录，注入首次编码失败并验证仅重试编码；真实 FFmpeg 编码、FFprobe 解码计数与首／中／末帧像素比较。另覆盖 1920 长边取消、临时目录清理、离开页面取消、监看恢复、浏览器入口限制和深浅主题、宽窄窗口。
- `test:world-offline-desktop-e2e`：运行 0.3.0 发布版程序，使用独立 WebView2 数据目录、真实 Tauri IPC 和 FFmpeg，完成 24 帧 H.264 导出；核对素材文件、尺寸、帧率、帧数和时长，并验证真实素材协议播放、播放推进及重新加载后的持久化读取。结束时清理本测试产生的媒体及独立浏览器数据，不使用生成模型。
- `cargo test --lib --no-default-features`：原生逐帧写入与参数校验、真实 H.264 编码及解码、损坏帧后的编码重试、运行中的 FFmpeg 取消，以及只清理本任务目录；同时回归既有 MP4 转换。
- 继续回归多机位监看、GLB 动作片段、多机位序列及整体视频工坊，完成 TypeScript 检查与生产构建。

Chrome 浏览器回归模拟 Tauri IPC，WebGL、PNG、FFmpeg 和 FFprobe 为真实执行；Rust 测试直接覆盖原生任务实现。发布版 WebView2 的导出、保存、播放及重新加载已通过真实 IPC 串联验证。各类失败注入及逐帧时间比较仍由浏览器和 Rust 用例覆盖，尚未逐项在桌面发布版重复。测试不调用真实生成模型、不消耗模型额度。
