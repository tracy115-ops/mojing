# 小说内容质量与真实阅读验收（0.3.3）

本轮验收的对象是读者看到的正文：人物为什么行动、行动是否改变处境、线索是否有来源并得到推进、前文是否承接、语言是否准确且有辨识度。生成成功、导出成功、工具数量和模型评分都不能替代这些判断。

## 已修正的写作链路

| 环节 | 发现的问题 | 本轮处理 |
| --- | --- | --- |
| 章节规划 | 大纲直接进入写作，容易将无动机的隐瞒、重复检查、通用神秘人影写成长章 | 正文前审读并修正大纲；保留原始方案、修改理由和未解决问题。已有大纲也须审读；正文或前文改变会使缓存失效。审读不代表文学质量认证 |
| 写作依据 | 旧大纲被当成已发生事实；工具有时读取陈旧章节集合 | 统一读取当前故事树；原始简介优先；规划与正文分开；只读取当前章以前的正文 |
| 章间承接 | 仅取前章末尾约500字，容易遗漏道具交接、人物选择与消息来源 | 最近三章提供正文；更早章节使用带正文指纹和引文的记录，失效时明确标注为片段，不冒称全章覆盖 |
| 自动分段 | 下一段缺少本章已写完整正文，容易重开场景；超出字数会被程序直接截掉 | 后续段落收到本章完整已写内容；取消正文硬截断；完成关键行动与后果，不用省略号强行制造钩子 |
| 文风与节奏 | 固定感官、微动作、线索配额和反转要求，会把创作变成填模板 | 移除主要写作提示中的机械配额；允许必要心理、直接叙述和安静场景；用选择、后果和信息变化决定篇幅 |
| 正文审读 | 均分与关键词容易掩盖硬矛盾；模型也会漏判、误判 | 审读完整正文及所给前文，给出具体问题与实际段落依据。严重问题不能被高均分抵消；DeepSeek V4 审稿与修订启用推理并留出输出预算、请求时间 |
| 修改采用 | 泛化润色可能缩写长章、丢失结尾，或夹带无益的装饰性改写 | 按原文段落预览并逐处选择；精确替换，保留未修改文字；采用后再次审读；保留上次修改前备份 |
| 自动推进 | 审稿、修订失败后仍可能继续后文，放大已有错误 | 保留草稿并暂停；未解决问题保持待修订。候选修改增加严重问题或没有改善时保留原稿 |

这是对当前章节链路的修正，不能据此声称仓库内每一个历史叙事算法都已获得内容有效性的证明。

## 真实样稿中暴露的问题

原始测试作品《末班车之后》：当代都市悬疑；30岁的女公交司机林岚，在雨夜收车发现黄色帆布包，包内只有一张日期为次日的旧车票；现实规则，调查依靠可验证线索。

原稿约2966字符。通读发现收车、绕车、逐排检查占用过多篇幅；雨、灯光、身体冰凉和眼睛意象反复；拍照后又开柜取包补拍；拍照摆回原状的动机不足；公交车“副驾驶位”缺乏现实依据；询问侧门缺少当前场景中的因果接点。章末新布条提供的实际推进也很弱。

这些问题部分来自旧大纲本身，单独改几个句子不能解决。因此本轮同时检查规划、写作、前文输入、审稿与修订。

保留的失败对照：

- `novel-reading-quality-2026-11-17T11-23-12-401Z`：真实模型改写引文后无法对应正文，审稿未完成。之后改为段落编号，由程序取实际原文。
- `novel-reading-live-2026-11-17T11-29-28-213Z`：模型建议把“眼睛”换成“泪”，并增加保安回避动作。人工判断没有内容收益，整版未采用。
- `novel-reading-live-2026-11-17T11-37-34-514Z`：只采用删除重复补拍、减少重复袖口描写，拒绝会影响相邻段落承接的改文。重新规划又出现藏票、说谎缺少充分动机的问题。
- `novel-reading-live-2026-11-17T11-46-04-769Z`：真实稿件中“当天最后售出的纸票”和“当天未撕过纸票”矛盾，过零点后仍说次日未到；快速审稿漏判。不能因为它给了85分就判为合格。
- `novel-reading-live-2026-11-17T11-51-28-773Z`：启用推理后的真实审稿被原有120秒请求期限中断，保留失败，随后修正推理请求期限。

以上均是实际服务调用和真实浏览器界面操作；不是打桩文学评分。失败稿和拒绝建议用于说明限制，不会改写为成功证据。

## 程序检查的实际边界

段落编号校验只证明引用来自给定原文，不能证明模型对这段文字的解释正确。章后事实记录也仍须判断是否被引文支持。模型可能过度称赞氛围，建议添加更多手势，或漏掉不同段落之间的矛盾；这些问题必须通过通读来发现。

长篇还有额外限制：最近三章之外依赖摘要与事实记录，超长单章会明确节选；上下文预算不足时停止自动写作。三章测试不能证明十万字小说、全部题材和长期伏笔均已通过，不能宣称“消除AI味”或自动达到出版水准。

推理审读比快速生成耗时更长；它提高核对的机会，也不能取代编辑判断。

## 本轮最终记录

实际服务为已配置的 DeepSeek `deepseek-v4-pro`。正文生成关闭推理以保留正文预算；大纲审读、正文审稿、局部修订启用推理。本次创作在真实浏览器界面操作，未拦截响应、替换生成结果或导入业务模块来冒充用户操作。

来源必须区分：第一章初稿来自本轮稍早一次真实生成，作为本批次的基线恢复；第二、三章由编辑输入章节意图，经过应用的大纲审读再生成正文。因此这不是无人干预自动驾驶的三章测试。所有原稿、规划、审稿、候选修改及拒绝理由保存在交付包 `verification/live-reading`，最终可读样稿见 [《末班车之后》三章编辑稿](samples/末班车之后-三章编辑稿.md)。

第一章模型修订中，关于改变时间、强加警察惊讶的两处没有采用。第二章候选虽然有局部可用措辞，整体却引入新的规则与时间问题，故没有在修订弹窗中采用。编辑单独录入修改时复用了“回拨这个号码”的措辞，记录为人工统一编辑。修改计划、每处原文/改文/理由、编辑前后全文均保留，没有把人工修稿算成模型生成质量。

另通过故事圣经正常编辑窗口同步了一条模型派生的“旧车票特征”：把已售出改为票夹中未售出的相邻票号，统一备用票的日期栏规则，保留原始“发现时日期为次日、现实调查”的故事承诺。该调整有独立前后记录。它改变了审读上下文，因此此前报告不能算最终设定下的有效通过；界面已核对提示重新审读。编辑稿第一、二章在这次设定同步前的再审已返回；第三章最后再审至收尾未返回有效新报告，保留旧稿记录并明确过期，不用旧报告冒充新稿通过。

再审也暴露误判：第二章被建议把必要心理全部外化、把师徒间一句质问视为性格不符，仍在机械执行旧文风公约。这类建议未采用。关于票务室上报冲突的收束、雨景密度和第一章末日期表达的清晰度，则保留为继续编辑的方向。审稿启用推理后依然需要判断意见本身。

本次内容结论是：链路更能保留和发现问题，样稿经编辑后修正了一批因果、常识与承接硬伤；自动初稿和模型修订仍不能免审直接发布。旧仪表盘的分数和“阶段”也不构成这三章的文学结论。下一步质量工作应继续比较初稿与修订稿的实际阅读收益，尤其是信息推进、角色声音、篇幅分配和长篇承接，不能再用增加工具面板代替这些结果。
