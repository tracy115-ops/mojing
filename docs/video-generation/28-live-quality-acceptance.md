# 0.3.2 真实模型与画质验收

2026-11-17 在 Windows 发布程序中，通过正常配置、规划、生成、审片和素材回流界面调用真实服务。使用隔离的 WebView2 用户目录、真实 Tauri IPC 和磁盘；关闭网络拦截，没有替换模型结果或注入生成产物。

**画质结论：尚未通过可交付质量验收。** Agnes 视频请求被服务队列阻塞；替代 H3 通道能生成可播放视频，但仍有道具、文字标记、跨镜人物／场景一致性与动作遵循问题。流程测试成功不能解释成画质已达标。

## 固定剧本

《雨后》，计划 15 秒、16:9、三镜各 5 秒。一位成年东亚女性林夏，黑色齐肩短发，深蓝风衣、白衬衫，同一把黄色长柄伞，同一处雨后咖啡馆门口。

1. 全景：拿着收拢的黄伞向门口走。旁白“雨停了，街道慢慢醒来。”
2. 中景：把合拢的伞靠到墙边。旁白“她收起雨伞，停下脚步。”
3. 近景：抬头看向右上方阳光，自然微笑。旁白“新的一天，正好开始。”

要求面容、衣服与布景稳定，无其他人，无文字标记，无异常张嘴和肢体变形。

## 实际服务结果

| 环节 | 实际服务／模型 | 结果与边界 |
| --- | --- | --- |
| 剧本规划 | DeepSeek / `deepseek-v4-pro` | 真实切片、分镜、实体提取成功；前几次失败推动了失败恢复、上下文、schema 和输出额度修复；在人工确认前没有生成付费图片 |
| 角色与场景 | Agnes / `agnes-image-2.1-flash` | 生成角色、服装、三视图、场景和三镜关键帧，人工逐图选择；皮肤仍有生成感，背景存在模糊牌匾 |
| 收伞首帧 | 同上 | 参考图中的撑伞状态多次污染关键帧；仅改英文优先级未解决。正常界面加入伞布、伞尖、伞柄与头顶状态的具体中文描述后，生成了合拢黄伞 |
| 原定 I2V | Agnes / `agnes-video-2.5-flash` | 三镜批量及单镜重试未取得视频；多次 HTTP 503 `video_queue_full`，另有网络发送失败。不能评价该模型本次视频画质 |
| 原配音 | Edge TTS | 三段均 WebSocket 1006，没有生成音频 |
| 替代配音 | SiliconFlow / `FunAudioLLM/CosyVoice2-0.5B` | 正常设置后真实生成三段 MP3，完整解码成功；时长 3.576、2.688、2.928 秒，均有非零音频能量；没有主观音色试听结论 |
| 替代 I2V 尝试 | SiliconFlow / `Wan-AI/Wan2.2-I2V-A14B` | 实际 HTTP 403 `Model disabled`；只读模型发现随后仅返回 H3，没有把不可用模型记为成功 |
| 替代 T2V | SiliconFlow / `MiniMaxAI/MiniMax-H3` | 正常视频工作台提交四次，四条均成功落盘、完整解码。第一条撑开透明伞；改具体状态后生成合拢黄伞，再分别生成放伞、抬头微笑两镜 |

H3 四条原片实际都是 H.264 + AAC、1376×768、24 fps、124 帧、约 5.167 秒。旧适配器登记的 1280×720、5 秒属于预设值，工作台已改为探测保存文件的实际属性。模型返回内容没有裁掉或涂掉标记。

H3 在当前能力契约下只使用文本控制，四次请求都没有首帧或角色参考。它们是单独的真实 T2V 样片，不能算 Agnes I2V 成功，也不能作为同一参考图条件下的公平模型比较。

## 目检发现

| 版本 | 观察 | 判断 |
| --- | --- | --- |
| 第一条全景 | 人物和相机运动基本稳定，但要求合拢黄伞，实际为撑开的透明伞；店面文字明显，右下角有“AI生成”标记 | 不采用 |
| 具体状态全景 | 黄伞保持合拢，方向基本正确；实际双手斜持腰前，没有遵循单手垂在腿旁；取景未完整呈现全身 | 仅用于流程测试 |
| 放伞中景 | 能观察到合拢伞逐步放下并松手，主要动作大体完成；店面牌匾仍有文字，衣领、面容和布景与其他镜头不完全一致 | 仅用于流程测试 |
| 微笑近景 | 抬头和微笑可见，人物和相机动作连续；脸型、衬衫领型和背景门墙有变化，过程中张嘴，仍有“AI生成”标记 | 仅用于流程测试 |

每条原片均经过 FFprobe、FFmpeg 完整解码和六个时间点的抽帧目检；前两条另保留正常播放器播放到结尾的状态。抽帧和解码不等于专业放映审片，也没有替代主观声音检查。

三条选用视频又经正常“检查后进入正式审片”回流到原项目。为验证原生合成，逐镜明确记录“仅用于真实合成测试，商业画质不通过”，再通过界面选择、批准、锁定并合成。真实测试成片约 15.584 秒、1376×768、372 帧，保留三条模型视频原有 AAC 音轨；导入协议明确保留原音轨，因此三条 CosyVoice 旁白单独交付，没有冒充已混入成片。原片实际长于各镜计划，未裁剪到精确 15 秒。

## 本次真实联调修复

规划失败恢复、全局设定保留、配音文本过滤、DeepSeek JSON 输出额度、人工视觉验收入口、Agnes Image 种子范围、参考与镜头状态优先级、编辑关键帧后继续生产，详见 [功能验收清单](./27-feature-acceptance.md)。

真实 H3 素材回流还暴露了大视频导入失败：`fetch(data URI)` 在 WebView2 中拒绝约 2.4 MB 的地址，现改为直接 Base64 解码。发布版回归使用超过 2 MB 的有效 MP4，经真实 IPC 读取，核对完整文件 SHA256、尺寸、时长和采样画面。

## 证据与后续验收

本机原始目录为 `artifacts/live-quality-2026-11-17T03-29-36-424Z/`。发布压缩包的 `verification/live-quality/` 包含请求模型与参数、失败消息、项目快照、真实 PNG／MP3／MP4、抽帧和 `report.json`；接口密钥和临时签名凭证不进入证据包。

本轮同时使用了修复前后多个发布构建，各轮程序指纹见 `generation-build*.json`。最终安装包的程序指纹与完整自动化回归另记在 `BUILD-INFO.json`。早期失败样片不能冒充全部出自最终构建。
